# Braga design system — v2.1 decisions

**v2.1 · 26 Oct 2026.** From this version `design-system/` is the design system of record. The handoff
(`handoff/`: v2 tokens, proposals, specimens, `HANDOFF.md` D-01–D-25, `AUDIT.md` D-026–D-035) stays as
received and is never edited; where it and this file disagree, this file wins. Rebuilding the site,
or anything else in the system, from `handoff/` alone gives a different result: read the handoff,
then apply the entries below in order.

Order of authority: owner > this file > `design-system/*.css` and `README.md` > `handoff/`.

| File | Holds |
|---|---|
| `tokens.css` | every value (unchanged role: the only file with a hex) |
| `tokens.json` | the same values resolved, for everything that is not this site (§3); generated by `npm run tokens:export`, checked by `npm run lint` |
| `README.md` | the stylesheets, the class contract and every pattern's DOM |
| `DECISIONS.md` | this file: what changed since the handoff, and the contract outside the site |

## 3. The system outside the site

Everything published under the owner's name follows the same tokens. Consumers read
`design-system/tokens.json` (from a sibling checkout, or `raw_base` + `design-system/tokens.json`)
and the faces listed in its `fonts` (OFL 1.1: they may be vendored with `public/fonts/licenses/`).
Hand-copied hex values are a defect: a consumer that carries its own palette must check it against
`tokens.json` in its tests.

### 3.1 README banner (D-051) — `braga-portfolio-docs`, `readme_quality.hero`

- 1600 × 640 PNG, light theme: `surface` ground, nothing outside a 72px safe area, 8px grid.
- Top row: **BRAGA** (BKribitz 800, −0.07em, `ink`), then ` · ` and the project kind as a label
  (BKribitz Mono 400, uppercase, +0.08em, `ink-2`). Right: the **status square** of the project's
  state (D-029, drawn, `ink`) and its label in the same label style.
- Body: title in BKribitz 700, −0.025em, `ink`; optional tagline as a label; descriptor in BKribitz 400,
  `ink`, at most 60 characters a line (D-050).
- Foot: repository facts as labels, **opened by a 1px `ink` rule** (D-044: the rule opens, nothing closes).
- **No accent**: a banner has no earned figure and no action (D-036). No dots, no circles, no gradients,
  no shadow, no image, no rounding. Separator is the middle dot (D-034), a glyph of the face.
- README statuses map to the five squares: Complete, Maintained → complete ■ · Functional → functional ▣
  · In development, Prototype, Foundation → in-build □ · Archived → archived ⊡ (under-revision ▤ has no
  README term yet). The label is always the README term.

### 3.2 Architecture diagram (D-052) — `braga-portfolio-docs`, `readme_quality.diagram`

- Mermaid, `theme: base`, light tokens, **the same theme the site draws its diagrams with**
  (`src/lib/vault/mermaid.mjs`, components.css "diagram"): `surface` ground; nodes `surface-2` with a
  1px `ink` border and `ink` text; edges 1px `ink-2`; clusters `surface` with a 1px `rule-c` border;
  edge labels on `surface`; BKribitz 14–15px, falling back to the reader's sans on GitHub.
- **One accent per figure** (D-036): the entry point the reader starts from, or the output the decision
  is read off, gets a 1px `accent-01` border. Text never takes the accent.
- No categorical colour coding of groups: subgraphs carry the grouping. Square corners.

### 3.3 Charts (D-053) — `bk-viz`

- IBCS only (D-015): actual `sc-ac` solid, previous year `sc-py`, plan `sc-pl` outline; good variance
  `var-pos`, bad variance `var-neg` always with ▲; **one highlight per chart in `hl` (= accent)**.
- Categorical hue in slot order (`categorical`, 6+ = `categorical-other`), grey for parts of a whole;
  the seven scales of `color.<theme>.scales`.
- Continuous fills (heatmaps, contours, choropleths): a one-sided magnitude takes the sequential
  scale `seq`; a diverging scale (`div`, `two`) only around a real midpoint (zero, a tie, a target),
  anchored at it, never at the data's own minimum. One band per scale step at most: a fill with more
  bands than its scale has steps cannot be read, so bin the data to the steps.
- Colour lives in marks, never in type: every label `ink` or `ink-2`. Figures in BKribitz Mono
  (tabular, slashed zero). No text below 12px. Hairline gridlines in `rule-c`, axes in `mid`.
- Light and dark from the same token names; figures carry a source line.

### 3.4 README badges (D-054)

Shields badges use the neutrals, never a judgement colour: label `ink` (`26282C`), message `ink-2`
(`5A5C61`). Status is a fact, not a traffic light.
