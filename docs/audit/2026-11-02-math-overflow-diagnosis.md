# Math overflow diagnosis — 2 November 2026

Read-only diagnosis against `/workspace/braga-portfolio-v2/dist`, using the repository static server and Playwright Chromium at 320 × 844, light theme, after `document.fonts.ready`. No production source, note, CSS, or gate changes were made. Only this report and diagnostic artifacts were written.

## Finding

All 11 reported G-17 pages reproduced: 13 formula boxes exceed their 288px columns by 3–20px. Every offending box has exactly one displayed variant. These are actual formula overflows, not false positives from hidden variants or an unloaded-font race. `G-17` compares `.math-body.scrollWidth > clientWidth + 1`; the selected formula's MathML itself exceeds its parent. The gate's truncated TeX preview can describe an inactive first variant, but its width decision is correct.

Six boxes are already at the 13px base-font floor. A seventh (learning rate) remains too wide when reduced from 13.09px to 13px. The other six boxes fit at 13px; their chosen sizes are too large because the build's width model underestimates actual MathML. `data-w` is an estimated width including the 1.2 margin and ceiling, not a browser measurement. The model scales script dimensions while CSS floors scripts/fraction descendants at 12px, making small-size width behavior nonlinear; bold native MathML spacing/column widths are further model inputs rather than browser-exact metrics. This diagnosis establishes measured underestimation, not one exclusive low-level glyph cause.

`breakVariants()` treats braced groups, left/right spans, fractions, and environments as atomic. It inserts a full `\quad` indentation on continuation rows. Most floor overflows are caused by that extra indentation added to already long atomic fragments, rather than content that intrinsically cannot fit at 13px. The learning-rate cases row remains intrinsically too wide in the existing variants.

## Bounded browser experiments

These were reversible DOM experiments only. All variants were tested individually at their computed font and at 13px; the full per-variant results are in `math-overflow-details.json`. Two further experiments changed only the active formula: increase its CSS width budget variable by 2em, and replace its 1em mspace indentation with zero. No content, fonts, or container sizes were changed.

- Increasing `--w` by 2 reduces the chosen font while preserving the 13px clamp; it fixes all six above-floor boxes, including graph definition.
- Removing the generated continuation indentation fixes 11 of 13 boxes without changing the selected font size. Graph definition has no such indentation and remains 308px. Learning rate remains 295px (294px at 13px).
- Combining the two experiments fixes 12 of 13 boxes. Learning rate still needs a smaller equivalent expression or explicit author layout. None of these experiments hides overflow, enables scrolling, reduces the 13px floor, or changes a gate.

Do not globally strip `mspace[width="1em"]` in production: some space is authored and meaningful. The experiment identifies the layout cost; an implementation should change/mark only the indentation generated by `layout()`.

## Safe implementation recommendation

1. Remove or narrow generated continuation indentation at narrow container widths, preserving authored spacing. Make a targeted change in `layout()` or give generated indentation an identifiable marker; avoid general MathML mspace overrides. The 11 successful indentation experiments preserve every symbol and relation.
2. Improve the conservative width model or its rounded `data-w` budget to handle the six measured misses. The +2em experiment is evidence of sufficient local headroom, not proof that a global +2 policy is optimal across the vault. Prefer a calibrated margin/model change tested across all formulas, or explicit note layout for the exceptional graph set expression. More cautious variant selection can also help the expanded-binomial note: a narrower existing variant fits at this width, but the selected 280–320 range variant does not.
3. Rewrite the learning-rate display with the explicit definition $\Delta\eta=\eta_{\max}-\eta_{\min}$, then use $\eta_{\min}+\Delta\eta\,c_t$ in the second cases row. Put the definitions of $c_t$ and $p_t$ on separate aligned rows. This preserves warmup/cosine semantics, both case conditions, and all parameters while shortening the row that still measures 294px at the floor. Verify the actual rendered result; this author rewrite was proposed, not browser-tested here.
4. If avoiding a generic fitter change, author explicit compact equalities/definitions in the affected notes: graph $G=(V,E)$ with $V$ and $E$ on their own lines; conjugate-prior updated parameters; Fourier summand shorthand; latent component log-likelihood shorthand; perplexity token-probability shorthand; quantile interpolation index/fraction definitions; median odd/even index shorthand; split saddle eigenvalue inequalities across rows. Keep every definition and condition. Such rewrites require mathematical review and rendered tests.
5. Rerun the full site matrix after implementation, including 320 light/dark, other viewport widths, min-font gate, horizontal overflow, and formula fit. The prior actual run is 826 pages / 2262 contexts / 33 failing gates (22 G-05 and 11 G-17), not a zero-failure baseline. This report diagnoses the 11 formula pages; it does not assert that the rest of the matrix is now green.

## Implementation follow-up

The actual modified pipeline exposed feedback that the earlier browser-only experiments intentionally did not model: removing the generated quad also reduces estimated `data-w`, which can increase the chosen font. Median and saddle consequently remained too wide after regeneration even though the fixed-data-w experiments fitted them. The bounded implementation uses no global width fudge: remove only generated continuation indentation and rewrite four notes with equivalent compact author layouts (graph, learning rate, median, saddle). Median is split into separate odd/even equations because a compact cases block still enlarged the selected font enough to overflow. The final actual-pipeline focused matrix passes all 22 contexts (11 pages × 320px × two themes), totaling 108 formula boxes with base-font sizes at least 13px. See `2026-11-02-math-overflow-fix.md` for coverage and limits; a final compiled full-site rerun remains with the controller.
