# design-system/ — Braga design system v2, as stylesheets

Plain CSS, no build step, no dependencies. Every page loads `src/styles/global.css`, which imports these files in order. The values come from `handoff/_ds/tokens` (v1 base) merged with `handoff/ds-update/tokens` (v2, wins) and the adopted proposals in `handoff/ds-update/proposals`; the patterns come from `handoff/specimens/Design System v2 - Site.dc.html` with its spacing kept to the pixel (BUILD-BRIEF rule 10).

`npm run lint:css` (`scripts/lint/css-rules.mjs`) fails on a hex outside tokens.css or anywhere under `src/`, on a font size below 12px / 0.75rem, on a missing contract class, on a token pair below its contrast threshold, and prints the contrast table. The two dark copies in tokens.css must stay identical; the lint checks that too.

## Rules the stylesheets assume

- No inline `style=` except the custom property that positions a mark: `style="--x: 50%; --w: 34%"` on `.ev-fill` / `.ev-mid` and chart marks.
- No hex outside tokens.css; every colour is a `var(--…)`.
- No font size below 12px (`--t-mono-sm`); chart SVG text is CSS 12px, so give an SVG a CSS height rather than a scaling viewBox (A-04).
- Vertical space between document siblings is set only by the FLOW section of base.css; no element carries its own margin.
- Colour lives in marks, never in type. The accent is text only for the one earned figure per view (`data-accent` on a `.metric`, `<mark>` in prose, the active `.toc` number).

### Sub-classes the patterns use (not in the contract; documented here for Agent B)

- Footer: `.site-footer` goes **inside** a `.grid-container` (`<footer class="grid-container"><div class="site-footer">`); four `.col-3.site-footer-group` on a `.grid`, each `.label` + `ul.site-footer-links`; then `.site-footer-bar` with `.site-footer-mark` (BRAGA) and `p.site-footer-colophon`.
- Cover: `.cover` is its own grid with a hairline and 64px top padding — place it directly in `<main>`, not inside `.section`. Children: `.cover-rail` (`.label.cover-index`, a `<dl>` of `.label` dt / dd), `.cover-body` (`p.label.cover-name` with the accent square drawn by CSS, `h1.cover-role`, `p.prose.cover-lead`, `.cover-foot` with `.label` spans and `a.label.cover-cta` + `.glyph`).
- Section heading: `.section-heading` is its own grid; `p.section-heading-kicker` (two spans: number, word), `.section-heading-claim` (h2.display + p.prose), `a.section-heading-link` (+ `.glyph`). `.section-heading + .listing` gets 32px.
- Document opener: either `header.doc-opener.grid` with `.col-3` (trail) and `.col-9` (title, `.doc-lead`, `.doc-meta`: 24px between each, set on `.doc-opener > [class*="col-"] > * + *`), or stacked inside `article.doc` (24px grid gap, no margins). The title may be h1–h3; it renders at `--t-h1`.
- Contents: `nav.toc` with `p.label`, `ol > li > a` holding `span.toc-num` + `span`. Mark the active item with `aria-current` on the `<a>` (title to ink, number to accent).
- Metric strip: `.metric-strip > .metric > .metric-value + .metric-label.label`; `data-accent` on the earned `.metric`. Three columns, 24px gap; below 560px the figures stack (a seven-digit value at the 30px floor does not fit a third of 390px).
- Evidence: `figure.evidence` with `p.label`, `p.evidence-heading`, `.ev-bars > .ev-bar > .ev-label + .ev-track (> .ev-fill [+ .ev-mid]) + .ev-value`, then `figcaption` with `<b>Source:</b>`. `data-accent` on the winning `.ev-bar`. In a document the figure comes from a `> [!bars]` callout (src/content/README.md §5) as `figure.evidence[data-width="wide"]` on the wide track; its own margin is zero at no specificity (`:where`), so the FLOW rules of base.css space it like any figure.
- Status vocabulary: `.status-list > div > .status + .status-use`, on the 9 of a `.grid` whose 3 holds the `.label` (Work index). The block sits `--block-gap` under the listing (`.listing + .grid`), or under the section heading while the listing is empty; a draft mark after it (`.grid + .doc-meta`) keeps 16px.
- Document grid (projects, essays, About, kitchen sink; `src/layouts/Document.astro`): `header.doc-opener.grid` then a `.grid` with `nav.toc.col-3` and `article.doc.col-9` (`col-start-4` when there is no contents rail). `.doc-opener.grid + .grid` ends 64px above the footer, as `main > .doc:last-child` does for the stacked utility pages.
- 404: `.doc-opener > .doc-numeral-row > span.doc-numeral + h1` (the numeral in the display face, as the Templates specimen sets it; the opener closes on 32px). Fig. 404-1: `figure.fig > .fig-matrix[role="img"]` holding an empty corner, two `.fig-matrix-head` column heads, then per row a `.fig-matrix-head[data-row]` and two `.fig-matrix-cell` (`.fig-matrix-name` or `.fig-matrix-count`, then `.fig-matrix-tag`); `data-accent` on the one earned cell (components.css section 7).
- A paragraph that is one link (no sentence around it): `p.link-line > a`. The link gets a 24px box (44 × 44 below 768) because the inline-target exception does not apply.
- Sections: a `.section` that opens with a `.section-heading` drops its own hairline (the heading's ink rule opens the block), and a following one drops its top padding, so consecutive home sections are one `--section-pad` apart. A `.cover` that is the first child of `<main>` drops its hairline (the shell's closes the header).
- Targets below 768: nav and footer links, `.doc-meta a`, `.link-line a` (base.css 3.7) and the trail, end bar, cover CTA and forward links (layout.css section 10) are 44 × 44. The footer groups sit two by two below 768.
- Chart SVG classes: `.axis .gridline .cap .curve .cursor .marker`, text in `.ink` for values. Roles for marks: `.sc-ac .sc-py .sc-pl .var-pos .var-neg .hl .cat-1…5 .cat-other .catg-1…4` on `.ev-fill`, `.mark`, `.swatch` or any SVG shape; a label carrying `.var-neg` gains the ▲ and stays ink.
- Code block: `.code[data-lang][data-wrap="on|off"] > .code-bar (> span + .code-tools > button.code-wrap + button.code-copy) + pre > code` with `.tok-kw .tok-fn .tok-str .tok-num .tok-cm .tok-op`. The two buttons are 44 × 44 below 768 (gate G-05).
- Mathematics: `.math > .math-body[tabindex="0"] > math[display="block"]` + `span.eq-no`; inline `<math>` in the sentence. Native MathML only (see the decisions below).

## Theme

`<html data-theme="light|dark">` is the stored override (the pre-paint script in Base.astro, about 260 bytes, the first script in `<head>`); no attribute follows the OS; `.dark` on any element inverts that element alone and paints its own canvas. Theme-color metas: `#E4E6EA` light, `#191A1D` dark (Base.astro). They come before the pre-paint script, which gives both the stored theme's colour on load; the toggle sets both to the painted canvas colour after a click.
